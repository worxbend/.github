<h2>🔌 IoT and edge hardware</h2>

<p>
  Small Wi-Fi microcontroller boards — the ESP32 and ESP8266 families — running firmware I wrote, usually paired with a server on the network that I also wrote. <strong>TCP</strong> below means a raw network socket: a plain byte-by-byte connection between two programs, with no HTTP, no JSON and no text framing layered on top.
</p>

<p>
  <strong>The clearest example is the ESP32-CAM camera link, which is one system split across two repositories.</strong>
  <a href="https://github.com/w0rxbend/spycam"><code>w0rxbend/spycam</code></a> is the <strong>camera half</strong>: firmware for the ESP32-CAM, a small Wi-Fi board with a camera attached, which captures JPEG images and pushes the newest one over a long-lived raw TCP connection.
  <a href="https://github.com/w0rxbend/instachron"><code>w0rxbend/instachron</code></a> is the <strong>server half</strong>: a Go service that listens on that TCP socket, receives and stores the frames, and then republishes them over HTTP with restreaming, optional detection and upscaling, and a timelapse recorder.
  <a href="https://github.com/w0rxbend/spycam-s3"><code>w0rxbend/spycam-s3</code></a> is the same camera half rebuilt for newer ESP32-S3 boards, and it stamps a camera identifier into every frame header so several boards can feed one instachron server at once.
</p>

| Project | What it does | Built with |
| --- | --- | --- |
| [w0rxbend/spycam](https://github.com/w0rxbend/spycam) | Camera half of the pair. ESP32-CAM firmware that captures JPEG frames and pushes the newest one over a raw TCP socket, dropping stale frames and reconnecting with backoff when the network or the server goes away. | C++, PlatformIO |
| [w0rxbend/instachron](https://github.com/w0rxbend/instachron) | Server half of the pair. Listens on the raw TCP socket, receives and stores the incoming JPEG frames, and republishes them over HTTP with restreaming proxies, detection, upscaling and timelapse. | Go, Vue |
| [w0rxbend/spycam-s3](https://github.com/w0rxbend/spycam-s3) | The same camera client rebuilt for ESP32-S3 camera boards, with a pin map for the GOOUUU OV2640 layout and a per-camera identifier in each frame header. | C++, PlatformIO |
| [worxbend/frostfire](https://github.com/worxbend/frostfire) | ESP32 firmware that briefly closes a relay wired across a computer's power-button header, so the machine can be switched on or off remotely. Fixed-length pulses, relay off after every pulse and at boot, token required. | C++, PlatformIO |
| [worxbend/frostfire-backend](https://github.com/worxbend/frostfire-backend) | The guarded web service in front of that relay, layered into API, application, domain and infrastructure, with a safety policy checking every request before it reaches the hardware. | Python, FastAPI |
| [w0rxbend/led-matrix-controller](https://github.com/w0rxbend/led-matrix-controller) | ESP8266 firmware driving an 8x8 panel of addressable LEDs, running a TCP server on port 7777 that accepts compact binary commands, and falling back to its own Wi-Fi access point when unconfigured. | C++, ESP8266 |
| [w0rxbend/echo](https://github.com/w0rxbend/echo) | Sits between webhook sources and those LED panels: post a JSON event, rules decide which animation plays, and echo pushes it over TCP to one or more panels with automatic reconnection. | Go, Prometheus |
| [w0rxbend/echoctl](https://github.com/w0rxbend/echoctl) | A command-line tool for driving echo. It deliberately speaks only to echo's HTTP interface and never to the panel's raw firmware protocol. | Scala 3 |
